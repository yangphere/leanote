# 技术栈现代化后续重构清单

本清单记录已经识别、但不阻断当前技术栈现代化任务树完成的结构性工作。条目只有在建立独立任务、明确验收并获得批准后才进入实现。

## MOD-001 请求上下文贯穿数据访问链

- **状态**：延期，不阻断当前父任务。
- **问题**：MongoDB 官方驱动以 `context.Context` 表达取消和截止时间，但现有 controller 与 service API 没有上下文参数。
- **本轮处理**：MongoDB 兼容层集中设置显式、可配置的操作超时；不增加第二套 service API，也不把上下文改造混入驱动迁移。
- **延期原因**：全链路传播会同时改变 controller、service、db 以及大量内部调用签名，显著扩大 70 个 mgo 影响文件的变更面，降低契约回归的可归因性。
- **启动条件**：MongoDB 驱动迁移和 Revel 迁移均稳定完成，Golden 与 USN 回归持续通过。
- **建议验收**：请求取消或截止时间能够终止对应数据库操作；后台任务使用显式根上下文；不再由兼容层内部创建无来源的请求上下文；测试覆盖取消、超时和资源释放。

## MOD-002 Linux ARM64 镜像与 PDF 渲染

- **状态**：延期，不阻断当前父任务。
- **问题**：首版发布镜像只保证 `linux/amd64`，现有 PDF 导出依赖外部渲染器，ARM64 可用性和输出兼容性尚未形成证据。
- **本轮处理**：发布完整功能的 `linux/amd64` 镜像，不发布缺少 PDF 能力的 ARM64 变体。
- **延期原因**：为 ARM64 更换或适配 PDF 渲染器会扩大行为面，且可能改变导出结果，不应混入交付链迁移。
- **启动条件**：找到受维护、许可证兼容、同时支持 amd64/arm64 的渲染方案，并建立 PDF 冒烟夹具。
- **建议验收**：同一版本的双架构镜像均能启动、连接外部 MongoDB、完成登录和 PDF 导出；镜像清单包含两种架构；失败时不静默禁用功能。
