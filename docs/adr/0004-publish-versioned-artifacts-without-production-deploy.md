# ADR-0004：发布带版本的制品但不自动部署生产

- **状态**：Accepted
- **日期**：2026-08-25

## Context

现有 Travis 配置只做存活检查，`package.sh` 依赖 Revel CLI，仓库没有可验证的镜像或版本制品发布流程，也没有获得任何生产环境权限或部署约束。

## Decision

- Pull Request 与普通 push 只运行测试、构建、Golden、生成资源漂移和打包验证。
- `v*` 标签只有在全部门禁通过后，才把 tarball 附加到 GitHub Release，并把同版本 Docker 镜像发布到 GHCR。
- 首版镜像只发布 `linux/amd64`，必须保留包括 PDF 导出在内的现有能力；ARM64 记录为 `MOD-002`。
- 镜像以非 root 用户运行、连接外部 MongoDB、把上传与文件目录暴露为持久化挂载点；镜像和 tarball 不包含真实凭据、用户数据或本地生成物。
- 工作流不自动部署任何生产环境。

## Consequences

- 开源使用者可以获得可追溯、可重复的版本制品。
- 发布只依赖 GitHub 提供的仓库令牌，不需要生产凭据。
- ARM64 使用者暂时需要自行构建；项目不会发布功能残缺的官方 ARM64 镜像。
- 生产部署策略仍由各自环境负责，不被仓库工作流隐式决定。
