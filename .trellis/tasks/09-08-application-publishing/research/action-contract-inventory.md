# Publishing 动作/输入输出/失败清单（2026-09-24，规格审核版）

本清单源自 `conf/routes`、现有 controller/service/model；“现有输出”是兼容对照，不代表现有实现满足权限/失败要求。`*` 路由与 catch-all 的具体方法及 JSONP/status/header 由 `interface-http` 用真实请求冻结，不能根据方法名臆测。各组每个 action 都要有成功、拒绝和依赖错误的 fixture，错误翻译由 HTTP 适配层负责。

本叶已激活且四项实现合同已于 2026-09-24 确认；本清单是合同和研究材料，不是实现或运行证据。分享期限使用 `ExpiresAt`，`SetNote2Blog` 使用 raw boolean 全成功映射，评论 receipt 使用 actor+submissionId 独立唯一凭据，评论 outbox 使用取消/transport handoff CAS。后续实现仍须按验收矩阵提供真实证据。

实现核对：S1/S4/S6 的 `(owner, resource, recipient)` 是按个人/组分别 partial unique 且互斥的键，非法/重复旧记录 preflight 阻止就绪；B-NOTIFY/DELETE/RETRY 共用 design 状态表，receipt 完整保留 30 天后仅压缩、永久保留提交身份。`TransportHandedOffAt` 不证明 SMTP 接受，闸门后未知结果不得重投已删除正文；验收见 AC-PB1-SCHEMA、AC-PB4-RECEIPT-GC、AC-PB4-HANDOFF。

Q-P9 已决：仅评论/回复提交的 `Blog.CommentPost` 新增必填 `submissionId`（32 位小写十六进制的 128-bit 随机值），不携带该字段的旧评论客户端不兼容，必须在任何写入前失败；其他博客互动、分享旧客户端的输入合同不因此改变。浏览器两处评论入口均须每次有意提交生成新值，同一次网络重试复用旧值；接口需以真实请求冻结无身份/冲突错误的 status/body。

Q-P1 已决期限字段 `expiresAt` 与独立清除标志 `clearExpiresAt=true` 的创建/更新/省略/拒绝合同分别落在 S1、S4、S6；个人与组授权不可只改其中一个入口。跨层真实 HTTP 状态及浏览器证据仍由 interface/presentation/delivery 补齐，不能把合同已决写成实现已通过。
